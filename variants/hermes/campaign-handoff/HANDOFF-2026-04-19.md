### 2026-04-17 evening — r7 baseline (later disproven)

### 2026-04-17 late evening / 2026-04-18 — r7.2 dense+MoE A/B and the drift investigation

MoE came in at **0/5 first-attempt, 5/5 final** (wrapper rescue at ceiling — the model never emitted the right first tool but always converged after one nudge). ### 2026-04-18 evening — r7.3 remediation playbook

With the corrected baseline in hand, we dispatched **7 parallel diagnostic workers** (α prompt anatomy, β first-turn divergence, γ retry divergence, δ tool surface, ε toolset restriction, ζ prompt rewrites, η correction-text rewrites) and then a **judge θ** to synthesize. - **Layer 1** — the prompt geometry is hostile (HERMES.md sits at slot 10 of 12 in the system prompt, behind an 11.8 KB skills index).
- **Layer 2** — the tool array is adversarial (29 tools, alphabetically sorted, with `delegate_worker` at index 13 and 3.6× smaller than the anti-dispatch sibling `delegate_task` immediately above it).
- **Layer 3** — the text itself offers escape hatches (HERMES-variantD.md L82, L140-145, L153-157 all let the model "re-classify to one-shot" or "do quick orientation reads").
- **Layer 4** — dense and MoE fail at different decode points (dense always emits SOME tool but the wrong one; MoE often emits no tool at all and end-of-turns after the marker).

We implemented **Layer 1** (a new `file_readonly` toolset of just `read_file` + `search_files`, restricting all probe runs to `delegation,todo,clarify,file_readonly`) and **Layer 2** (HERMES-variantE.md with the five escape hatches stripped + correction-message escape clause removed from the wrapper). 34-trial probe (15 dense + 15 MoE + 4 one-shot regression).

The two real wins from r7.3: zero `tool_not_found` events and zero tripwire mutations, confirming the restriction is structurally sound even if it doesn't yet force dispatch.

## 8. Known traps and gotchas

These bit us during r7.2/r7.3 work; documented so the next agent doesn't re-discover them the hard way.

- **Wrapper SIGTERM truncation.** `timeout` killing `hermes chat` mid-call doesn't flush the parent session JSON. The dispatch may have actually happened (child worker session exists on disk) but the parent's record is lost. r7.2 wrapper has a fallback recovery path that scans recent sessions by mtime + model match, but it's brittle — sometimes picks the child as the parent. r7.3 fixed worst-case timeout by raising TIMEOUT to 900s but the underlying issue remains. **Implication:** any apparent "no dispatch" outcome on a long task should be cross-checked by looking for child sessions with the parent's dispatch goal as their first user message.

- **Source tag isn't persisted in session JSON.** Hermes does NOT write the `--source` flag value into the session JSON. You cannot grep sessions by tag — you must correlate by timestamp + first-user-message content matching. Painful for forensic analysis. (Worth filing upstream as a feature request.)

- **`hermes chat --resume` with `-t` flag is untested edge case.** When the wrapper resumes a session for retry, pass the same `TOOLSETS` value as the original invocation. The retry behavior under a different `-t` value has not been characterized.

- **`SKILL.md` is a Trial 9 mutation attractor.** The Jira-cron task induces SKILL.md mutations on dense (it happened twice today during r7.2 work). MoE didn't show this pattern. Reverts are documented in archive artifacts. Under r7.3's `file_readonly` toolset this can't happen because `skill_manage` isn't in the toolset, but **if you ever revert to a fuller toolset for any reason, watch SKILL.md.**

- **HERMES.md auto-discovery via `prompt_builder`.** The system walks cwd → git root looking for HERMES.md (Worker C's r7 finding). **Don't move the HERMES.md file path on the VM** without updating the prompt-builder logic. Also: this is why putting HERMES.md in slot 10 happens automatically — the prompt-builder appends it as the `context_files_prompt` block based on cwd-walk, not based on a config flag.
