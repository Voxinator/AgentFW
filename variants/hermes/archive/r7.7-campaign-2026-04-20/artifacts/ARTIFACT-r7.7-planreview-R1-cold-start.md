### A. Blockers

1. **[§5 pre-flight, line 175]** `export OMLX_API_KEY="$OMLX_API_KEY"` — **Blocker** — This is a no-op if the operator's shell doesn't already have `OMLX_API_KEY` set. The plan notes the key lives in an env var but never tells the fresh agent how to obtain/verify it (and §12 says "never commit <the key>" which hints at the value but doesn't tell me how to load it). Preflight almost certainly fails silently without it. **Fix:** Replace with `if [ -z "$OMLX_API_KEY" ]; then echo "OMLX_API_KEY not set — ask operator before continuing" >&2; exit 2; fi` and add explicit operator instruction in §17: "☐ Confirm operator has exported OMLX_API_KEY in shell; do not proceed without it."

2. **[§5 line 175]** `/Users/briantaylor/Projects/AgentFW/probe-preflight.sh` — **Blocker** — The plan references this script as though it exists, but it's listed in §14's "expected md5" table and the MORNING-SUMMARY lists it as NEW in Fix 5. A fresh agent doesn't know whether the file is already on disk at the stated path. If git status left it un-tracked or a later operator action moved it, the whole preflight halts. **Fix:** Add a check `test -x probe-preflight.sh || { echo "preflight script missing — see MORNING-SUMMARY Fix 5"; exit 2; }` and in §17 add "☐ Verify probe-preflight.sh exists and is executable BEFORE running it."

3. **[§5 line 179-183]** `md5 /Users/briantaylor/Projects/AgentFW/probe-preflight.sh ...` — **Blocker** — macOS `md5` outputs a different format than Linux `md5sum`. The expected baselines in §14 are bare hex digests with no filename. If the fresh agent runs this on Mac and just eyeballs output vs. the table, the compare works; but any automated check will fail. More importantly, `/tmp/probe-r7.6-P1C-logs/judge-trial.py` at line 635 has md5 `709ef98a...` — `/tmp` is ephemeral and will almost certainly be gone if the fresh session is >1 reboot later. **Fix:** (a) Clarify md5 tool (`md5 -q` on macOS for bare hash); (b) mark the `/tmp/...` line as EXPECTED-EPHEMERAL and note recovery path (reapply Fix 2 patch from ARTIFACT-r7.6-P1C-fix2-impl.md).

The plan authorizes "many many agents" and autonomous execution overnight, but oMLX restart is a manual gate. **Fix:** Add CLI restart recipe or declare this as a mandatory operator-interaction point in §13.

5. **[§6.3 lines 214-229]** Research-worker brief assumes `~/.hermes/hermes-agent/` is reachable from the research worker — **Blocker** — The worker runs on the Mac-side fresh session; `~/.hermes/hermes-agent/` lives on the Parallels VM. The plan never says "use ssh ubuntu-vm" and never provides the ssh target name (§3 says "on ubuntu-vm per Parallels" once, implying the alias, but it's never declared as a known ssh-config entry). **Fix:** Add a §5.1 subsection "VM access for workers: all VM-path greps must be prefixed `ssh ubuntu-vm -- <cmd>`. 6. **[§7.2 line 289]** "session persistence is inline in `run_conversation` at `run_agent.py:~9109`" — **Blocker (over-precise)** — This is both a prediction problem (E) and a blocker: the implementation worker is instructed to patch at ~line 9109. ### C. Unstated preconditions
