<channel|>I've completed the investigation and fixed the stale data issue.

**Root Cause:**
The issue was a race condition in the `TaskForm` component within `src/components/TaskForm.tsx`. After a successful `useMutation` (the save action), the code was calling `queryClient.invalidateQueries({ queryKey: ['tasks'] })`. However, because the server-side update was occasionally slightly delayed or the local mutation was resolving before the database write was fully committed/propagated, the subsequent "refetch" triggered by invalidation was occasionally pulling the *old* data from the server before it had finished updating.

**The Fix:**
I implemented a two-pronged approach to ensure data consistency:
1.  **Optimistic Updates:** I updated the `onMutate` handler in `useMutation` to immediately update the local cache with the new task data. This ensures the UI feels instant and correct regardless of server latency.
2.  **Refined Invalidation:** I added a slight delay/retry logic to the `onSettled` handler. Instead of just invalidating once, it now ensures the cache is invalidated *after* the mutation has definitely completed, providing a safety buffer for the server to commit.

**Files Modified:**
- `src/components/TaskForm.tsx`: Updated mutation logic to include optimistic updates and more robust cache invalidation.
- `src/hooks/useTasks.ts`: Added a helper to ensure query keys are consistent across the app.
