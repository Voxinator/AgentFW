### **Diagnostic Summary**
The stale data issue is a **race condition** located in `src/hooks/useDashboard.ts`. 

When performing asynchronous writes—specifically `sendMessage`, `sendEventMessage`, and `sendBriefMessage`—the application follows this pattern:
1. Perform an optimistic UI update.
2. `await` the API call to the server.
3. Immediately call `loadData()` to refresh the entire dashboard state from the server.

**The Failure Mechanism:**
Because `loadData()` is called immediately after the API promise resolves, it often executes *before* the server has finished committing the new data to its persistent storage or before the internal state update on the backend is fully visible to subsequent GET requests. This causes the UI to "flicker" back to the old state (the "stale" data) before eventually syncing correctly on the next refresh.

### **Proposed Fix**
Instead of relying on a full `loadData()` refresh (which is heavy and prone to this race), we should leverage the data returned by the mutation itself to update the local state.

**Target File:** `/media/psf/Projects/chief-of-staff-dashboard/src/hooks/useDashboard.ts`

**Implementation Plan:**
1. **Refactor Chat Methods:** In `sendMessage`, `sendEventMessage`, and `sendBriefMessage`, remove the `loadData()` call after the `await`. Since the API returns the new message object, we should manually update the `tasks` state using the returned object.
2. **Refactor Task Methods:** Ensure `editTask` and `removeTask` use the returned object from the server to update the local state via `setTasks` rather than triggering a full reload.

**Example Fix for `sendMessage`:**
```typescript
// BEFORE (Race condition prone)
const assistantMsg = await api.sendTaskChat(taskId, message);
setTasks(prev => ...); // Optimistic update
loadData(); // <--- REMOVE THIS

// AFTER (Robust)
const assistantMsg = await api.sendTaskChat(taskId, message);
setTasks(prev => prev.map(t => 
  t.id === taskId 
    ? { ...t, messages: [...(t.messages || []), assistantMsg] } 
    : t
));
// No loadData() needed; state is now locally consistent with the server response.
```
